# Verification scope for 1.1.0

The grouping preparation checks exact membership and unique ownership, stable metadata, official Skill frontmatter, UI invocation fields, Python syntax, local Markdown links, selected private-path/credential patterns and retained licenses. Maintainer checks bind each independently copied candidate, its SHA256SUMS and ZIP member bytes to the reviewed source inventory. Historical candidate files remain unchanged; derived selection indexes can point to the new candidate.

Available synthetic regressions are run against both source and an independent candidate copy. Environment-dependent skips are reported separately. The exact run counts and artifact identities are maintained with this release preparation; no historical total is presented as the count for this reorganized group.

Windows privilege-dependent symlink operations and unavailable Bash entrypoints may be skipped and are reported separately. No live remote authentication, current receiver permission profile, unattended operation or fresh-client activation is established by portable tests.

Version 1.0.0 identifies the chosen first stable public contract. It does not turn a structural pass or a limited synthetic check into universal behavioral, scientific, visual, legal or security proof. GitHub creation, push, tag and Release are separate from local candidate preparation. No plugin marketplace or other distribution platform was submitted during this grouping work.

## Current source regression result

The stable group source runs 98 synthetic regression tests: 93 passed, 5 environment-dependent skips, no failures. Twelve of them are new in 1.1.0. Five cover the startup byte budget: a file within budget, a file over budget measured in UTF-8 bytes, the disabled check, the document roles that are counted, and a negative value as a usage error. Seven cover the declared-scope audit: the default mode still reads every Markdown file; a declared entry with exclusions checks only the active route, counts what it did not reach, and lists links into excluded directories; broken links on the active route are still reported; an unreached file with invalid UTF-8 is not read; the text report qualifies its pass with the scope; and invalid entries or exclusions are usage errors. Every test asserts that the audit root is byte-identical afterwards. Official Skill quick validation passes for every member. Candidate copies are independently checked and exercised before release preparation is closed; these counts do not represent independent model behavior.

## Behavioral comparison for 1.1.0

The maintenance rules were compared blind with the previous internal candidate. For each of six synthetic scenarios from the maintainer's acceptance set, two fresh agents received the same workspace and request, one with each version under a neutral name, and neither was shown the expected behavior. The scenarios were: closing a phase after a new version was accepted; a read-only question; cleaning a `tmp` folder that holds unique acceptance evidence beside a regenerable image; listing junk under Full access without permission to delete; a scope-specific instruction to judge and delete; and two files with the same bytes but different delivery roles. The resulting file changes were checked against snapshots of each fixture.

Both versions handled all six correctly: no unauthorized or wrong deletion, no repeated request for authority already given, unique evidence kept, a regenerable file deleted only after a byte-identical rebuild, and no writes for the read-only question. The scenarios therefore did not separate the versions. The result shows that the new rules introduced no regression in these cases; it does not show an improvement. Each configuration ran once per scenario on one model family. Long-session, compaction, executor and other-model cases were not run.

The 1.0.1 change affected instructions, UI metadata and release documentation only. The 1.1.0 change adds one audit check, three options and their tests, a retention reference, plus instructions and templates; the Git closeout runtime is unchanged and its permission guidance gains a Claude Code section built from the client's published documentation and one dated local observation, not from a new helper test. The budget check measures file size and cannot judge whether remaining text is current. Automated checks cannot prove an independent agent's first conversation; verify actual invocation in the receiving client.
